# Three.js and device delivery

Apply the owner's Browser/Seeker app/Both choice and, for Seeker/Both, explicit bundled-or-hosted APK architecture before implementation. Both Android architectures produce signed installable APKs; Browser alone does not. These Three.js rules apply to website and Android rendering; [Android delivery](seeker-android.md) adds content-origin boundaries, lifecycle, wallet integration, signing and device verification. Offer [Game Room integration](game-room.md) only when the selected delivery includes a website. Build the selected game, not a connect button around a scene. Separate simulation from frame rate: fixed timestep with bounded catch-up, seeded randomness where reproducibility matters, and input actions shared by keyboard/pointer/touch. Physics/replays do not prove human play.

Use a supported renderer with feature detection and visible WebGL fallback. Resize using the container/ResizeObserver, update camera projection and drawing buffer; cap device pixel ratio (a tested 1–1.5 mobile baseline can help). Do not assume WebGPU everywhere. Reuse materials/geometries, instancing, bounded shadows/lights and compressed assets as appropriate. Dispose resources on teardown. Measure asset/triangle/draw-call budgets on the selected phone rather than promise 60 FPS.

Use `100dvh`, safe-area insets and reserved HUD/touch space. Pointer capture and `touch-action` belong on gameplay surfaces, not the whole document. Menus scroll without moving characters. Avoid keyboard-only actions, tiny targets, banners covering play and hover-only guidance. Pause during dialogs; support focus return/Escape and readable errors.

Try menu music at startup and decode loops early. The Android host allows media playback without a gesture for its approved game content; browsers may deny autoplay, so attach one first-gesture fallback. Honor persisted mute, keep it separate from suspended AudioContext and avoid stacked players. Background suspends; foreground resumes permitted music but never gameplay. Do not restart the menu loop for every screen. Invalidate stale wallet identity on account changes and refresh entitlement at the agreed admission boundary; do not trigger repeated wallet prompts, repurchase a paid round or interrupt admitted play merely because the app resumed. Clamp time after screen lock and do not silently fast-forward competitive play. Pause/recover on WebGL loss instead of leaving a blank canvas. Follow [sound effects](sound-prompts.md) and [music](music-prompts.md) for voice limits, separate buses/sliders, stingers and seamless loops.

Follow [the visual-realism guide](visual-realism.md) for model detail, PBR texture sets, lighting and visual acceptance checks. Load art with progress/retry/fallback; procedural art is suitable for labeled prototypes. Check asset provenance/licences before copying another game's models, voices or branding.

Verify: complete win/loss/restart; selected input methods; 390×844 portrait; phone landscape; constrained GPU; resize; no wallet; chosen browser/native wallets; account change mid-check; rejected sign-in; expired/insufficient locks; unavailable/429 evidence; pending transaction if implemented; background audio; context loss; share cancellation. For Both, run the shared gameplay cases on both artifacts and each platform's wallet/lifecycle cases separately. Report untested physical-device cases honestly.

Sources: https://threejs.org/manual/pages/responsive.html ; https://threejs.org/manual/pages/cleanup.html ; https://threejs.org/docs/pages/WebGLRenderer.html

## Adaptive quality and release presentation

Use the pure [quality governor](../assets/quality-governor.mjs) with the game's measured tier table. Three-second windows step down below 50fps; two good windows above 58fps permit recovery, with a skipped window after changes and a 30-second cooldown after a failed step-up. Ignore >250ms gaps/background time. Reduce full-detail character count, then crowd count, shadow size and DPR; retain realistic same-model LODs, not primitive replacements. Log changes with a scrubbed `[<Game>]` prefix. These are control thresholds, not a promise of measured frame rate. Record actual device observations or untested.

Use the approved logo as a dimensioned WebP/PNG `<picture>` in the menu `<h1>`, with the game name as alt. All UI/HUD/errors/disclosures/lore/ads/wallet identity and store text follow the chosen locales; test real dictionaries and Android resource filtering, not country flags. For blood/dismemberment games, persist Full / Reduced / Off in title and pause, default Reduced in Store builds; Off removes gore visuals and SFX, Reduced removes dismemberment and softens wounds. Do not add gore to unrelated games.

Use deterministic capture hooks to advance/freeze the real simulation at a representative moment. Capture native-resolution frames with safe HUD areas, without development labels or unrelated wallets. Run the [release-pitfalls checks](release-pitfalls.md) before packaging.
